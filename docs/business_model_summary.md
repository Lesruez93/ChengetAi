# Business Model Summary

One-page business model summary for ChengetAI.

| Field | Response |
|---|---|
| **Problem** | Mobile-money scams run the same scripts across African markets — wrong-deposit reversals, fake jobs, fake investment, fake loans and grants, SIM swap, OTP and identity phishing — on EcoCash, M-PESA, MTN MoMo, Airtel Money, OPay and every other wallet. Three gaps compound it: generic spam filters miss code-switched local-language text; reporting leads nowhere, because people are told to report but not to whom or how fast; and there is no shared citizen-accessible scam-number database, least of all across a border. |
| **Primary user** | Individual mobile-money users (consumer app); mobile-money agents and SME till operators (Agent Fraud Sentinel). |
| **Beneficiary** | The same primary users, plus the wider financial-inclusion goal — reduced scam losses protect trust in digital finance for previously-excluded groups (rural households, first-time smartphone owners, older adults). |
| **Customer or payer** | Consumer features are free (freemium). Paying customers are mobile-money agents/agent networks/SMEs (Sentinel licensing) and, longer-term, telcos, banks and national regulators (aggregated scam-signal licensing). |
| **Value proposition** | Detect, report safely, reach help — in that order. Real-time scam verdicts grounded in the user's own market, with plain-language explanations; a next-step pathway attached to every non-safe verdict rather than a bare label; anonymous reporting that still counts; crowd-sourced number reputation including cross-border reach; and anomaly-flagged transaction review for agents who otherwise have no fraud tooling at all. |
| **Cross-border advantage** | A scam number reported in Lagos is visible to a user in Accra. No single-country tool can offer that, and it is the one thing that gets better rather than worse as the product spans markets — the network effect is the moat. |
| **Revenue or funding model** | Freemium (consumer) + B2B per-agent/per-till Sentinel licensing + institutional licensing of aggregated, anonymized scam-signal data to telcos, banks and national regulators. Philanthropic/development funding is a plausible fourth stream for the consumer-protection side, which is the part least able to pay for itself. |
| **Cost drivers** | LLM API calls (classifier), hosting (FastAPI + Supabase Postgres), SMS delivery (Twilio, report confirmations). Most scale-sensitive first: LLM calls scale with message volume, which is why the zero-marginal-cost baseline classifier exists as a fallback rather than only as a comparison. Per-market costs that are **not** software: verifying support contacts, and language coverage. |
| **Partnerships** | A mobile-money agent network or telco district for the initial pilot in one launch market; longer-term, national telecoms and financial regulators as plausible institutional co-funders of a shared cross-border scam-number signal. |
| **Pilot market** | One agent network or telco district in a **single** launch market (bounded, measurable scope) — not all seven at once. See `docs/deployment_plan.md` for the explicit pilot-site field and current status. |
| **Adoption risks** | Cold-start on crowd-sourced reputation (a scam database is worth little until it has reports, and reports need users). Agent networks' willingness to share transaction data under a data-sharing agreement. LLM API cost growing faster than revenue (mitigated by the baseline classifier fallback). And the market-specific one: **coverage breadth outrunning coverage depth** — seven markets in the code is cheap, seven markets with verified support contacts, local partnerships and real language coverage is not. |
| **Success metrics** | Classifier precision/recall against real reported messages, measured per market rather than in aggregate (an average hides a market performing badly). Sentinel true-positive rate against agent-confirmed fraud cases. Reporter engagement/retention on number reputation. And the one that matters most for the safety framing: **what share of users who receive a scam verdict go on to open the support pathway** — a detection tool whose help screen is never opened has not protected anyone. |
